# Fictional-data policy

All public examples, screenshots, tests, and fixtures must be invented for this
repository. Use reserved domains such as `example.invalid`, obvious demo site
codes, and identifiers beginning with `DEMO`, `EXAMPLE`, or `FICTIONAL`.

Do not lightly alter real records and call them fictional. Do not reproduce a
private source's field layout, mappings, aliases, terminology, identifiers,
network rules, folder conventions, or error output. When a requirement comes
from private experience, restate the generic behavior and design a new fixture
independently.
